## 🚀 Deployment

### Prerequisites
- ✅ Microservices running (Keycloak, API Gateway, all 7 services)
- ✅ Anthropic API key (get at https://console.anthropic.com)
- ✅ Python 3.9+ with pip

### 3-Step Setup

**1. Configure**
```bash
cd python-services/mcp-server

# Ensure .env has these 3 keys:
cat .env | grep -E "ANTHROPIC_API_KEY|MCP_CLIENT_SECRET|GATEWAY_URL"
```

Expected output:
```
ANTHROPIC_API_KEY=sk-ant-v0-...
MCP_CLIENT_SECRET=changeme-mcp-secret  # From Keycloak
GATEWAY_URL=http://api-gateway:8080
```

**2. Install**
```bash
pip install -r requirements.txt
```

**3. Run**

Development:
```bash
uvicorn app.main:app --reload --port 8090
```

Docker (with existing stack):
```bash
# Already in docker-compose.yml — just run:
docker-compose up -d mcp-server
```

Server is ready at `http://localhost:8090`.

## 🧠 How It Works

### Agent Loop (Pseudocode)

```
1. User sends message → Guardrails sanitize input (PII masking, injection blocking)
2. Add to session history
3. Call Claude API with:
   - System prompt (fraud detection, inventory rules, etc.)
   - Current conversation history
   - Tool definitions (7 tools)
4. Claude reasons and calls tools (if needed)
5. Execute non-sensitive tools immediately
6. APPROVAL GATE: If tool is cancel_order or update_inventory:
   - Set requires_approval=true
   - Store pending_action
   - Return to user with action for confirmation
7. User calls /chat/approve
8. Execute the pending action
9. Resume reasoning with result (step 3)
10. Guardrails sanitize output (strip costs, add disclaimer)
11. Return final response to user
```

### The 7 Tools

| Tool | Input | Output | Approval? |
|------|-------|--------|-----------|
| `get_order_details(order_id)` | Order ID | Full order, items, customer | ❌ |
| `check_fraud_score(order_id)` | Order ID | Score 0-100, risk level, factors | ❌ |
| `check_inventory_levels(product_id?)` | Product ID (optional) | Stock count, reorder point | ❌ |
| `get_recent_orders(user_id?, limit=10)` | User ID (optional) | Last N orders | ❌ |
| `flag_for_review(order_id, reason, score?)` | Order ID, reason | Review entry created | ❌ |
| `cancel_order(order_id, reason)` | Order ID, reason | Cancellation record | ✅ Yes |
| `update_inventory(product_id, qty, reason)` | Product ID, qty, reason | Inventory updated | ✅ Yes |

### Input Guardrails (InputGuard class)

Blocks:
- 15 prompt injection patterns ("ignore previous instructions", "jailbreak", etc.)
- PII data: credit cards, SSN, Aadhaar, PAN, passports, email, phone
- Messages > 10,000 chars

Example:
```
User: "Customer john.doe@example.com card 4111-1111-1111-1111 is suspicious"

Sanitized: "Customer [EMAIL_REDACTED] card [CREDIT_CARD_REDACTED] is suspicious"
```

### Output Guardrails (OutputGuard class)

Strips:
- API keys, passwords, JWT tokens
- Cost/margin/profit data (internal only)
- Other PII in responses

Adds:
- Policy disclaimer on all agent responses

Example:
```
Agent: "Total $99.99, our cost $45, margin 55%"

Sanitized: "Total $99.99 [COST_REDACTED] [MARGIN_REDACTED]

---
*Note: This response was generated by an AI agent. All sensitive operations require human review and approval. For concerns, contact support.*"
```

## 🔌 API Integration (Frontend)

### Normal Turn

```javascript
// User sends message
const response = await fetch('http://localhost:8090/api/ai/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    session_id: sessionId,  // null = new session
    message: "Check order ORD-123 for fraud"
  })
});

const { session_id, response, requires_approval, pending_action } = await response.json();

// If requires_approval is false, show response to user
// If true, show confirmation dialog with pending_action details
```

### Approval Flow

```javascript
// User clicks "Approve" in the dialog
const approvalResponse = await fetch('http://localhost:8090/api/ai/chat/approve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    session_id,
    approve: true,  // or false for rejection
    reason: "Fraud confirmed. Customer contacted."
  })
});

const { response, requires_approval, pending_action } = await approvalResponse.json();

// Agent resumes reasoning and returns final response
```

## 🔐 Security Architecture

### Authentication Flow

```
Agent (Python)
    │
    ├─ (At startup) OAuth2 Client Credentials
    │   POST /realms/ecommerce/protocol/openid-connect/token
    │   { grant_type: "client_credentials", client_id: "mcp-server", client_secret: "..." }
    │   ↓
    │   Keycloak returns JWT with admin role
    │
    └─ (Per tool call) Use JWT
        GET /api/orders/admin/{id}
        Authorization: Bearer <JWT>
        ↓
        API Gateway validates JWT via JWKS endpoint
        Injects X-User-Id: "agent" header
        Order Service returns order data
```

### Sensitive Operations

Only two operations require user approval:
1. **`cancel_order()`** — Stops an order, initiates refund
2. **`update_inventory()`** — Modifies stock levels

**Why?** These are the only operations that:
- Are irreversible without manual intervention
- Affect customer satisfaction (cancellation)
- Affect warehouse operations (inventory)

Safe operations (read + flag) execute immediately.

### Approval Gate Logic

```
if tool_name in ["cancel_order", "update_inventory"]:
    state.requires_approval = True
    state.pending_action = {
        "tool": tool_name,
        "input": user_input,
        "tool_call_id": ...
    }
    return response + "Awaiting your approval"
else:
    execute immediately
```

## 📈 Performance & Scale

| Metric | Value | Notes |
|--------|-------|-------|
| **Response time** | 2-5 sec | Includes Claude API, tool execution, guardrails |
| **Max concurrent sessions** | 10 (default) | Use `--workers 4` for higher concurrency |
| **Session memory** | ~1 KB per session | 1,000 sessions ≈ 1 MB RAM |
| **Token/turn** | 150-300 tokens | Depends on order complexity |
| **API rate limit** | None (internal) | Gateway rate-limiting applies |

**For production scale (>100 concurrent users):**

1. Use async workers:
```bash
uvicorn app.main:app --workers 4 --loop uvloop
```

2. Replace in-memory sessions with Redis:
```python
# See AGENT_README.md for Redis integration code
```

3. Add rate limiting (via API Gateway or reverse proxy):
```
Max 10 requests/sec per user session
Max 100 sessions per IP
```

## 🛠️ Extending the Agent

### Add a Custom Tool

**1. Implement in `agent_tools.py`:**
```python
async def my_new_tool(param: str) -> dict:
    """Tool description for Claude. This is auto-learned."""
    return await _get(f"{settings.gateway_url}/api/my-service/endpoint")
```

**2. Register in `agents.py` → `_get_tools_schema()`:**
```python
{
    "name": "my_new_tool",
    "description": "Detailed description of what this tool does",
    "input_schema": {
        "type": "object",
        "properties": {
            "param": {"type": "string", "description": "Parameter description"}
        },
        "required": ["param"],
    },
}
```

**3. Done.** Claude auto-discovers and uses the tool.

### Add Custom Guardrails

**Input guardrail** (block spam/injection):
```python
# In guardrails.py → InputGuard.INJECTION_PATTERNS
r"my_new_attack_pattern",
```

**PII pattern** (mask sensitive data):
```python
# In guardrails.py → InputGuard.PII_PATTERNS
"my_data_type": r"regex_for_detection",
```

**Output pattern** (strip internal data):
```python
# In guardrails.py → OutputGuard.SENSITIVE_PATTERNS
"my_internal_field": r"regex",
```
